# 153 PayPal Payment Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `153支付` tab next to the existing PayPal tabs, with multi-select batch submission of already-extracted PayPal BA links through a local FastAPI proxy to `https://pay.153.ink/paypal-pay/api`.

**Architecture:** Keep the current `UsPaypalPage.vue` as the PayPal workspace and add a third tab that reuses existing account/link selection patterns. Backend routes are added under `/api/us-paypal/pay153/*` and aggregate remote 153 jobs into the existing in-memory `JOBS` snapshots. The backend, not the browser, calls 153 so the app avoids CORS and can mark local accounts `paid` on completion.

**Tech Stack:** Vue 3, Vite, plain JavaScript static tests, FastAPI, Pydantic, pytest, Python standard library HTTP client.

## Global Constraints

- Do not iframe `https://pay.153.ink/paypal-pay/`; it sends `X-Frame-Options: DENY`.
- Do not change existing `PayPal 提链` or `协议支付` behavior.
- Do not implement 153 private Braintree Vault mode.
- Do not add new npm or Python dependencies.
- Use TDD: write failing tests before production code.
- Keep UI consistent with the current dark PayPal workspace.
- Support multi-select already-extracted accounts and batch submission.
